# ПРОМПТ: Telegram Mini App магазина MRAK8

Ты — топовый дизайнер и фронтенд-разработчик Telegram Mini Apps уровня Awwwards / FWA. Ты делаешь интерфейсы, которые скринят и пересылают друзьям. Твоя задача — спроектировать и собрать мини-апп магазина streetwear-бренда **MRAK8** (произносится «Мрак 8») с оплатой внутри Telegram и админкой для загрузки товаров.

Главное требование: дизайн должен взрывать мозг. Никакого «офисного» e-commerce, никаких шаблонных карточек с тенями, скруглённых кнопок по 12px и сеток как у маркетплейса. Каждый экран должен ощущаться как часть мира бренда, но оставаться быстрым и понятным: покупка за 4 тапа.

## 2. Концепция: «MRAK8 CENTRAL BOOKING & INTAKE CENTER»

Весь мини-апп — это **центр оформления**, текст со спины худи, превращённый в интерфейс. Покупатель здесь не «пользователь», а **SUBJECT**. Товары — **вещдоки** (EVIDENCE). Корзина — **изъятые вещи** (PERSONAL PROPERTY). Оформление заказа — **протокол**. Оплата — **оформление**. Всё «под наблюдением»: тонкий CCTV-оверлей, но вещь всегда главная.

Тон: ироничный, холодный, бюрократический, с самоиронией бренда «НЕ ДИЗАЙНЕР». Копирайт двуязычный: русский основной, английские служебные пометки как на худи.

### Сквозные визуальные приёмы
1. **CCTV-слой.** В углу экрана мигает красная точка `● REC`, тикает таймкод `CAM_08 · 2026-10-20 01:14:33`. Лёгкие сканлайны и шум (CSS/canvas, 2–4% непрозрачности). Отключаются при `prefers-reduced-motion`.
2. **Ростовая линейка из фото для протокола** (как фон для фото на документы при задержании): горизонтальные линии с делениями и цифрами. Это фон карточки товара и, главное, **селектор размера** (см. ниже).
3. **Номер дела.** Каждому юзеру присваивается номер `SUBJECT #08-XXXX`, который генерируется из Telegram user id. Номер показан в шапке и печатается в чеке.
4. **Штампы.** Красные «чернильные» штампы с неровной текстурой: `ОФОРМЛЕН`, `ИЗЪЯТО`, `SOLD OUT`, `CONTRABAND`. Появляются с ударом: scale 1.4→1, лёгкий поворот, тряска экрана 80ms, `HapticFeedback.impactOccurred('heavy')`.
5. **Восьмёрка-сканер.** Два эллипса логотипа — главный моушн-элемент. Это лоадер (кольца вращаются в 3D по разным осям, как радар), индикатор pull-to-refresh и анимация «сканирования» товара.
6. **Бегущая строка** `NO EMOTIONAL CONTRABAND. ALL SUBJECTS ARE MONITORED. НЕ ДИЗАЙНЕР. ` — тонкой полосой, как полицейская лента, между секциями.

## 3. Экраны и сценарии

### 3.1 Сплэш / «Оформление» (первый вход, 1.5–2 c, можно пропустить тапом)
Чёрный экран → белый логотип собирается: буквы MRAK падают сверху, эллипсы «8» раскручиваются из точки. Затем строчки печатаются моношрифтом:
`SCANNING SUBJECT...` → `@username IDENTIFIED` → `SUBJECT #08-4417 — ДОСТУП РАЗРЕШЁН`.
Аватар юзера (из `initDataUnsafe.user.photo_url`) появляется в рамке «фото на документы» с линейкой роста. При повторных входах сплэш сокращается до 400ms.

### 3.2 Каталог «EVIDENCE»
- Не сетка 2×N. Вертикальная лента из полноэкранных «дел»: на каждом экране огромное фото вещи на чёрном, сзади гигантский номер вещдока `#001`, который вылезает за края, сверху название узким капсом, цена моношрифтом, бирка-статус (`В НАЛИЧИИ`, `ОСТАЛОСЬ 3`, `SOLD OUT` — штампом).
- Скролл со scroll-snap и параллаксом: фото, номер и текст двигаются с разной скоростью.
- Наклон телефона двигает вещь (Telegram `DeviceOrientation` / `Gyroscope` API, Bot API 8.0+, с фолбэком на свайп).
- Переключатель вида: «ЛЕНТА» / «КАРТОТЕКА». Картотека — плотный список, как опись: номер, превью, название, цена, остаток. Для тех, кто хочет быстро.
- Фильтры в стиле штампов-чипсов: `ВСЕ / ХУДИ / ФУТБОЛКИ / АКСЕССУАРЫ / АРХИВ`.

### 3.3 Карточка товара «ДЕЛО #001»
- Переход из каталога: shared-element transition, фото «прилетает» на место. Пока грузится, по фото проходит красная скан-линия.
- **Перед/зад:** свайп влево/вправо поворачивает вещь в 3D (flip с перспективой). Для худи — `front.jpg` / `back.jpg`. Тап по детали увеличивает её в «лупе» с подписью-сноской, как фото улики.
- **Размер по ростовой линейке:** вертикальная линейка с делениями, на ней отметки S / M / L / XL на «высоте». Юзер тянет ползунок вверх-вниз, линейка щёлкает по делениям с haptic `selectionChanged()`. Рядом в моношрифте: замеры выбранного размера (длина, ширина, рукав). Недоступные размеры перечёркнуты красным.
- Описание как протокол: `МАТЕРИАЛ:`, `ПОСАДКА:`, `ПРИНТ:`, `ПАРТИЯ: 1/50`.
- Главная кнопка — нативная Telegram `MainButton` красного цвета: `ИЗЪЯТЬ — 6 900 ₽`. После тапа вещь уменьшается и улетает в «пакет для улик» в таб-баре, штамп `ИЗЪЯТО`.

### 3.4 Корзина «PERSONAL PROPERTY»
Прозрачный пакет для вещдоков с zip-полоской сверху (это отсылка к зипу худи) и бумажной биркой-описью. Позиции — строчки описи: `01. ZIP-HOODIE «НЕ ДИЗАЙНЕР» / L / ×1 ........ 6 900 ₽`. Удаление свайпом: строку зачёркивает красным маркером. Итог моношрифтом, MainButton: `ОФОРМИТЬ ПРОТОКОЛ`.

### 3.5 Чекаут «ПРОТОКОЛ»
Форма как бланк: поля с подчёркиванием, подписи мелким капсом сверху (`ФИО СУБЪЕКТА`, `ТЕЛЕФОН`, `АДРЕС ДОСТАВКИ`, `СПОСОБ ДОСТАВКИ`). Имя и телефон подставляются из Telegram (`requestContact`), но их можно изменить. Доставка: СДЭК / Почта России / самовывоз (список настраивается в админке). Внизу бланка галочка «С условиями ознакомлен» и место для «подписи». MainButton: `ОПЛАТИТЬ`.

### 3.6 Успешная оплата
Экран чернеет, на бланк с ударом и вибрацией `notificationOccurred('success')` падает красный штамп **«ОФОРМЛЕН»**. Ниже чек-квитанция: номер заказа `CASE #MRK-000123`, SUBJECT-номер, позиции, сумма, QR-код заказа. Кнопки: «Поделиться» (`shareMessage` / `switchInlineQuery`: карточка «Я оформлен в MRAK8») и «В каталог».

### 3.7 Мои заказы «ДОСЬЕ»
Список дел со статусами-штампами: `ПРИНЯТ → СОБРАН → ЭТАПИРОВАН (отправлен) → ДОСТАВЛЕН`. Трек-номер копируется по тапу.

### 3.8 Пустые и ошибочные состояния тоже по концепции
Пустая корзина: «Изъятых вещей нет. Подозрительно.» Ошибка сети: «СВЯЗЬ С ЦЕНТРОМ ПОТЕРЯНА», CCTV-помехи и кнопка «Повторить». Sold out: «Вещдок изъят другим субъектом.»

## 4. Админка «CONTROL ROOM»

Доступна по маршруту `/admin` внутри того же мини-аппа (и по команде боту `/admin`). Пускает только Telegram user id из переменной окружения `ADMIN_IDS`. Проверка — **только на сервере** по подписи `initData`.

Визуально — пульт охраны: стена мониторов (сетка камер-плиток со статистикой), моношрифт, зелёные пиксели заменены на красный акцент бренда. Функциональность важнее эффектов: админка должна работать быстро с телефона.

Функции:
- **Товары (CRUD):** название, slug, категория, описание, цена, старая цена, фото (несколько, с порядком; отдельные слоты «перед», «зад», «детали»), размеры с остатком по каждому, таблица замеров, статус (`черновик / дроп скоро / в продаже / sold out / архив`), номер вещдока.
- **Загрузка фото:** drag-n-drop и выбор с телефона, превью, обрезка под 4:5 и 1:1, автоконвертация в WebP/AVIF и несколько размеров на сервере, хранение в S3-совместимом хранилище.
- **Дропы:** запланировать выход товара на дату и время. В каталоге до старта показывается обратный отсчёт и кнопка «Уведомить меня» (бот пришлёт сообщение в момент дропа).
- **Заказы:** список с фильтрами по статусам, смена статуса, ввод трек-номера (покупателю автоматически уходит сообщение от бота), экспорт CSV.
- **Пост в канал:** кнопка «Анонсировать в канале» — бот публикует пост с фото товара и кнопкой, которая открывает мини-апп сразу на карточке (`startapp=product_<id>`).
- **Дашборд:** выручка за день/неделю, заказы, топ товаров, остатки, которые заканчиваются.

## 5. Оплата (касса)

Товары физические, поэтому **Telegram Stars не подходят** (по правилам Telegram их используют только для цифровых товаров). Используй **Telegram Payments с российским провайдером: ЮKassa** (основной вариант; провайдер подключается через @BotFather → Payments). Код должен позволять сменить провайдера через конфиг (например, Т-Касса, CloudPayments).

Флоу:
1. Клиент отправляет на сервер корзину и данные протокола. **Цены и остатки сервер берёт только из БД**, клиенту не доверяем.
2. Сервер создаёт заказ со статусом `pending`, на 15 минут резервирует остатки и через Bot API `createInvoiceLink` создаёт счёт (`currency: RUB`, позиции в `prices`, `provider_token` из env, `need_name`, `need_phone_number`, `need_shipping_address` по необходимости).
3. **Фискализация по 54-ФЗ:** передай чек в `provider_data` в формате ЮKassa (`receipt` с items, vat_code, payment_subject, payment_mode, телефон или email покупателя).
4. Клиент открывает счёт через `Telegram.WebApp.openInvoice(link, callback)`, по статусу `paid` показывает экран «ОФОРМЛЕН».
5. Бот обрабатывает `pre_checkout_query`: перепроверяет остатки и резерв, отвечает в течение 10 секунд.
6. На `successful_payment` сервер переводит заказ в `paid`, списывает остатки, сохраняет `telegram_payment_charge_id` и `provider_payment_charge_id`, отправляет покупателю сообщение-квитанцию, а в админ-чат (`ADMIN_CHAT_ID`) уведомление о новом заказе.
7. Неоплаченные резервы снимаются по таймеру. Учти идемпотентность и повторные вебхуки.

Сделай тестовый режим с тестовым токеном ЮKassa, чтобы прогнать весь путь без реальных денег.

## 6. Telegram-специфика (обязательно)

- `Telegram.WebApp.ready()`, `expand()`, `requestFullscreen()` там, где поддерживается, `disableVerticalSwipes()` (чтобы скролл не закрывал аппу).
- Учитывай `safeAreaInset` и `contentSafeAreaInset`: в fullscreen контент не должен залезать под кнопки Telegram.
- Тему Telegram не наследуем: бренд всегда тёмный. `setHeaderColor('#0B0B0B')`, `setBackgroundColor('#0B0B0B')`, `setBottomBarColor`.
- Нативные `MainButton` / `SecondaryButton` / `BackButton` для ключевых действий; `HapticFeedback` на всех значимых тапах.
- Корзина сохраняется в `CloudStorage`, чтобы переживать перезапуск и смену устройства.
- Deep links: `startapp=product_<id>`, `startapp=drop_<id>` открывают нужный экран.
- Подпись `initData` проверяется на сервере (HMAC-SHA256) на каждом запросе к API.
- Кнопка меню бота и кнопка в канале открывают мини-апп.

## 7. Технический стек (рекомендация, можно аргументированно изменить)

- **Фронт:** React + TypeScript + Vite, `@telegram-apps/sdk-react`, Framer Motion (переходы и жесты), GSAP (таймлайны сплэша и штампов), React Three Fiber только для 3D-восьмёрки, и только если она держит 60fps; иначе CSS 3D.
- **Бэк:** Node.js (Fastify) + grammY (бот, платежи, вебхуки), PostgreSQL (Supabase или своя), Prisma/Drizzle, S3-хранилище для фото (Supabase Storage / Yandex Object Storage), sharp для обработки изображений.
- **Деплой:** фронт на Vercel/Netlify, бэк и бот на любом VPS/Railway с HTTPS, вебхук бота.
- `.env.example` со всеми ключами: `BOT_TOKEN`, `PAYMENT_PROVIDER_TOKEN`, `ADMIN_IDS`, `ADMIN_CHAT_ID`, `CHANNEL_ID`, `DATABASE_URL`, `S3_*`, `WEBAPP_URL`.

## 8. Производительность и качество

- Первый экран меньше чем за 1.5 c на среднем Android в мобильной сети. Lazy-load изображений, blur-плейсхолдеры, фото в WebP/AVIF.
- Анимации на `transform`/`opacity`, 60fps. Тяжёлые эффекты (шум, 3D, гироскоп) автоматически отключаются на слабых устройствах и при `prefers-reduced-motion`.
- Контраст текста по WCAG AA, тап-зоны не меньше 44px, всё работает одной рукой.
- Ширина экрана от 320px.

## 10. Порядок работы и результат

1. Сначала покажи **дизайн-концепт**: moodboard-описание, дизайн-токены (цвета, шрифты, отступы, моушн-кривые и длительности), макеты ключевых экранов (сплэш, каталог, карточка с размерной линейкой, корзина, успех оплаты, админка) в виде работающего прототипа. Дождись моего одобрения.
2. Затем собери полноценный проект: фронт, бэк, бот, БД, оплату, админку.
3. В конце дай README: как создать бота в @BotFather, подключить ЮKassa, задать домен мини-аппа, заполнить `.env`, задеплоить и прогнать тестовую оплату.

Критерий успеха: человек открывает мини-апп из канала, первые 3 секунды залипает на сплэш, делает скрин и отправляет другу, а через минуту оплачивает худи, ни разу не споткнувшись в интерфейсе.
